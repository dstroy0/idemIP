A TCP/IP stack that allocates nothing.

idemIP is written in C11 for targets that have no heap and no operating system. Every unit that holds state is handed one uint8_t array by the caller, sized by a macro that unit publishes, and reads and writes nothing outside it.

The idea

The borrow is the instance

There is no file-scope mutable anywhere in src/, so two instances of a unit share not one byte, and the whole footprint of a build is the arrays the application declared.

bring-up, abridged
// the only header an application includes
#include "src/idemip.h"

// one array per unit, all .bss, sized by the macro that unit publishes
static _Alignas(IDEMIP_ALIGN) uint8_t netif_w[IDEMIP_NETIF_BORROW];
static _Alignas(IDEMIP_ALIGN) uint8_t arp_w[IDEMIP_ARP_BORROW];
static _Alignas(IDEMIP_ALIGN) uint8_t udp_w[IDEMIP_UDP_PCB_BORROW];

src/idemip.h is the only header an application includes. It adds no type, macro or call of its own; it names every unit's header, what the caller allocates, and the order things run in.

One calling convention, everywhere

Every entry in the library has the same signature. Arguments go into an operand block at offset zero of the borrow, the call takes the borrow and nothing else, and the result is read back out of the same block.

write · call · read
// every entry, without exception
void (*const entry)(uint8_t *restrict work);

IDEMIP_ARP_IO(arp_w)->find_args.ip = 0xC0A80101u;   // 1. write the operands
ArpTable.find(arp_w);                               // 2. call
if (IDEMIP_ARP_IO(arp_w)->status == IDEMIP_OK)      // 3. read the result
{
    memcpy(dst, IDEMIP_ARP_IO(arp_w)->mac, IDEMIP_MAC_LEN);
}
IDEMIP_OK
The call finished, and any result member is set.
IDEMIP_BUSY
No progress now: nothing waiting, no room, or still in flight. Call again on a later tick.
IDEMIP_ERR
Refused: a null borrow, a bad argument, or the wrong state. Do not retry.

That is the whole concurrency model. Nothing blocks, nothing sleeps, nothing spins, and no entry holds the CPU waiting on hardware or on a peer — a caller drives progress from its own millisecond timer. Three states, because three is what a timer-driven caller can act on: go on, come back, or stop.

The order

Clear, bind, tick

This is the one genuinely ordered thing in the library, and the only place on this page that is numbered.

  1. clear

    Every unit that exports a clear, on its own borrow. Every other entry refuses a borrow that clear has not run on, because a zeroed borrow reads a list link as index zero rather than as that unit's terminator.

  2. bind

    Phy.bind takes the driver and its Clause 22 management address; Dma.bind the same driver and the two buffer arrays; Netif.bind the phy borrow, the hardware address and the link MTU. Dispatch binds before Tick, because Tick's own bind takes the dispatch borrow.

  3. tick

    Three stages, in order, on a millisecond clock the caller reads once per pass: drain receive, run each service's timers, flush deferred transmit. A later stage consumes what an earlier one produced.

The tick enforces its own phase

src/core/tick.h holds the phase in its own context. Tick.open puts it at DRAIN, and an entry called out of its phase reports IDEMIP_ERR — so the services cannot silently run before the ring is drained. Each phase reports OK per step and BUSY when that phase is through.

phasewhat runsconsumes
DRAINevery frame the engine filled, dispatched and posted backthe receive ring
SERVICEARP, ND6, reassembly, IGMP, MLD, netif, timeouts — in dependency orderwhat DRAIN delivered
FLUSHwhat reported BUSY earlier, and the engine's finished transmit descriptorswhat SERVICE produced

The order of the IdemIpTickUnit constants is the dependency order: resolution before what waits on it, reassembly before the protocols that read a completed datagram.

Capabilities

Turn it down to what you need

A capability is a set of translation units. CMake selects them, so a capability that is off reaches the compiler as no file at all rather than as a file that compiles to nothing. Toggle these and the command line below follows — including the refusal, verbatim from CMakeLists.txt, when an edge does not hold.

 
your selection
cmake -S . -B ../build -G Ninja

Where one unit serves both IP versions, the version arm is its own translation unit and the build swaps in a stub for a version it left out: src/ip/pseudo.c holds the transport pseudo-header branch once, pseudo_v4.c and pseudo_v6.c are the two forms, and pseudo_v4_off.c and pseudo_v6_off.c answer a version this build does not carry.

Determinism in time

Each entry runs to a pad, not to its inputs

Space determinism is the borrow. Time determinism is the other half, and it is a build option: IDEMIP_ENABLE_TIME_DETERMINISM, off unless a build asks for it.

src/clock.h exposes four readings, and only the fourth costs anything:

now()
A uint32_t the caller reads, which wraps at 49.7 days.
stamp()
The reading the current pass entered on, so every deadline in one tick is compared against the same instant.
epoch()
IdemIpMs, 64-bit monotonic milliseconds. This is time.
determinism_pad()
The tuned pad, present only under the option above.
gradeunitcosttunes
COARSEmillisecondsno reading of its ownyes
FINE defaultmicrosecondsa second reading beside the epochyes
LITERALmicrosecondsa second reading beside the epochno — pinned to a measured ceiling

FINE is the default because every entry in this tree measures well under a millisecond, so COARSE would pad each one to many times its own cost. On the host in the archive the widest entry is idemip_cksum over 1500 octets at 0.10 µs, and ip4_frag.next at 0.08. Every value in the pad window was measured rather than chosen, and tools/dev_env/padwindow.py regenerates the block from a bench run — a slower target moves all of it, and the entries do not slow down by the same factor.

Deadlines wrap, so no comparison is a less-than

Millisecond deadlines wrap. Every comparison against one is the signed-difference form, never a plain <:

the only safe form
(int32_t)(a - b) >= 0

Turning the counts down

Every count is an #ifndef in src/idemip_config.h, so a definition reaching the compiler overrides it. These are preprocessor definitions rather than CMake options:

fewer TCP control blocks
cmake -S . -B ../build -G Ninja -DCMAKE_C_FLAGS=-DIDEMIP_TCP_PCBS=2

Each borrow is a formula over the counts, never a number, and each unit's .c carries static_assert(sizeof(<Unit>Ctx) <= IDEMIP_<UNIT>_CTX_BYTES), so a context that outgrows its budget fails the build naming the macro to raise.

The receive ring cannot starve

A retained frame stays in the buffer the DMA engine wrote it to, so its descriptor is not returned to the ring until the unit holding it is done. Every retention capacity is fixed at compile time, so the worst case is a number rather than a risk — and it is asserted:

src/idemip_config.h
static_assert(IDEMIP_RX_DESCRIPTORS > IDEMIP_MAX_PINNED_FRAMES,
              "the receive ring starves when every retaining unit is full");

Proof

Tests, and the things a green run cannot see

One CTest target per suite. A suite is a directory holding exactly one .c of file-scope void test_<name>(void) cases; harness.py turns it into unity_runner.c through Unity's own generator, and says so when the generator would walk past a case.

test/CMakeLists.txt maps each suite to the capabilities it drives. A suite whose capabilities are off is skipped loudly, because silently dropping it would leave a passing run that tested less than it looks like.

Constraints

What the code may not do

src/ is C11 with no heap, no auto, and no array with automatic storage duration. The only system headers it takes are <assert.h> for static_assert, <stddef.h>, <stdint.h> for the fixed widths, and <string.h> for memcpy, memset and memcmp. There is no <stdlib.h>, and nothing is parsed by the library.

Names are flat idemip_snake_case in one namespace. Sizes are powers of two so an index is a shift, because hardware divide is not on every target in the list. Word width is taken from UINTPTR_MAX, and 16-bit targets are supported. Wire fields are never read through a cast — always byte-assembled — because unaligned casts fault on strict-alignment targets. test/ and tools/ are exempt and read as plain host C.

Warnings are attached to an INTERFACE target so they reach the suites as well as the library:

every translation unit
-Wall -Wextra -Wpedantic -Wshadow
-Wconversion -Wsign-conversion
-Wcast-align -Wundef
the library on top of those
-Wstrict-prototypes -Wmissing-prototypes

Attached PRIVATE to the library, the warning set never compiled most of the tree: no .c in src/ includes tcp.h or ipv6.h, so those headers were built only by a test translation unit, which had no warning flags at all.
